## 干净应用

先确认工作区没有用户未提交改动，HEAD 为上述基线，再依次对 `series.txt` 内列出的补丁执行：

```sh
git apply --check /absolute/path/to/package/patches/0001-sdk-adapter.patch
git apply /absolute/path/to/package/patches/0001-sdk-adapter.patch
# 按 series.txt 顺序逐个检查并应用 0002～0007；前面的补丁应用后再检查后面的补丁。
# 不要使用包含 optional 的递归通配符。此时不执行 git add/commit，测试后自行提交。
```

补丁是 LF，不需要 `--keep-cr`。不要在已有集成修改的目录重复应用。应用失败时先检查报错，不要通过强制覆盖忽略冲突。

可选诊断补丁应在完整示例应用完毕后单独执行 `git apply --check` 和 `git apply`。默认构建关闭原厂逐帧 F/+，无需为此启用诊断补丁；示例原有业务/失败日志仍保留，并不代表完全静默。不要使用 git am；客户自行决定验证后的提交时间和提交信息。

## 编译前必须补齐

1. 将经确认的 **v1.369.6** `libtgCloud-kcp_82x.a` 放入 `project/tange/lib/`。文件名不变，但应核对 `manifest.txt` 中预期 SHA-256；该值只证明与开发分支库一致，不代替来源及 ABI 审计。
2. CDK 中打开 `project/txw82xApp.cdkproj` 并重新生成构建文件。不要从旧工程拷贝 Obj/Lst 或自动生成的 makefile。
3. 核对实际工具链版本和 `-mcpu=e804df -mhard-float -melrw`，工具链精确发行包及库 ABI 尚未实测确认。
4. 示例默认 CUSTOMER_ID=3，编译前脚本采用 `config_xt215.cfg`；CUSTOMER_ID=4 采用 `config828.cfg`。客户板卡必须调整引脚，不能直接烧录不匹配板型。
5. `pin_param.h` 保留原厂基线版本并继续受 Git 管理，未复制历史忽略规则。
6. 按要求保留开发版的测试 UUID/key 设置及 TG_DEBUG_MODE 默认状态，打包过程不改动该逻辑。测试身份不应给多台量产设备共用；量产烧号由客户按原流程处理。

## 已知边界

- `gettimeofday` 的时区叠加是继承开发示例的行为，不是通用 POSIX UTC 语义；客户已有校时方案时不能直接重复叠加时区。
- H264/MP4/JPEG 内存和缓存参数是资源配置，不是所有码率/分辨率下均适用。
- NAL 聚合缓冲按源实现为全局常驻单例；同时运行多个编码器需要另外审查互斥及生命周期。
- 旧录像版没有新模式中的统一 SD 故障恢复。不能把后续版本的修复能力写进本版说明。
- 新增 AT 测试命令仅在可选诊断包；其中格式化是异步受理，不代表已经格式化成功。
- 迁移代码仍需编译及实测，未进行整个 SDK 的缺陷修复或安全认证。
